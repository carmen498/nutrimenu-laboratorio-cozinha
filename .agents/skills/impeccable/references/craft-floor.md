# Craft floor

Apply this floor only after the authorized direction and scope are clear. The user brief, repository conventions, accessibility, and existing product behavior remain authoritative.

## Verify together

- **Hierarchy:** the primary task and current state are obvious; related content groups tightly and distinct groups separate clearly.
- **Contrast:** normal text meets 4.5:1 and large text meets 3:1 unless a stricter project requirement applies.
- **Typography:** Inter remains valid; measure, wrapping, zoom, localization expansion, and weight hierarchy work with real copy.
- **States:** relevant hover, focus, active, disabled, loading, empty, error, success, and permission states are complete.
- **Interaction:** controls work with keyboard and pointer, touch targets fit the use context, and focus remains visible and logical.
- **Motion:** animation explains change or feedback, stays interruptible and performant, and respects reduced motion.
- **Copy:** controls name their action; errors name the problem and recovery; claims come from supplied truth.
- **Coverage:** every requested requirement is present and verifiable without unrelated redesign.

## Challenge defaults

Treat these as prompts for evidence, not universal bans:

- repetitive same-size cards as the page's only organizing structure;
- nested cards, decorative gradients, or blur without a product reason;
- icon tiles, section numbers, or eyebrow labels that add no information;
- modals where inline or progressive disclosure would keep context better;
- emoji or arbitrary Unicode glyphs replacing the established icon system;
- ornamental motion, decorative metrics, or visual effects that compete with the task;
- one-off colors, spacing, radii, components, or interactions where the local system already owns the pattern.

Keep any of them when the brief, established visual language, or user task justifies them. The goal is deliberate design, not a new house style.
